# Development Rules & Engineering Standards

## Product: CloudSec-RAG

---

## 1. General Principles
1. **Zero Hallucination Tolerance:** Any patch command generated by the system MUST be backed by a verified cloud provider syntax catalog or retrieved CIS benchmark control. If unverified, the system must degrade gracefully to a descriptive advisory instead of outputting dangerous guesses.
2. **Zero Plaintext Secrets:** No credentials, API tokens, IAM secret keys, or customer PII shall ever pass into prompt generation or log persistence.
3. **Executable & Testable:** All core modules must be accompanied by unit tests and runnable without requiring paid external API subscriptions (using the built-in deterministic offline mock mode when API keys are absent).
4. **Idempotence & Rollback Guarantee:** Every patching operation must be idempotent and must include a paired rollback operation.
5. **Human-in-the-Loop Supremacy:** Automated remediation must default to dry-run preview mode. Direct execution requires explicit operator affirmation.

---

## 2. Code Quality & Standards
- Language: Python 3.10+
- Type Hints: 100% strict type hints across all function signatures.
- Schemas: Pydantic v2 schemas for all inputs, outputs, and storage objects.
- Error Handling: Explicit domain-specific exceptions (`HallucinationError`, `PromptInjectionAttemptError`, `SecretLeakageDetectedError`, `PatchValidationFailedError`).
- Test Coverage: Unit tests for parsers, sanitizers, injection detector, anti-hallucination engine, vector store, and patching engine.

---

## 3. Security & Operational Boundaries
- **OWASP LLM 01 (Prompt Injection):** Every untrusted log input must be passed through `InjectionDetector` prior to embedding or LLM dispatch.
- **OWASP LLM 02 (Insecure Output Handling):** Generated shell commands must be strictly validated against an approved command whitelist and syntax tree before dry-run execution.
- **OWASP LLM 06 (Sensitive Information Disclosure):** Ingestion pipelines must invoke `PrivacyScrubber` first.
